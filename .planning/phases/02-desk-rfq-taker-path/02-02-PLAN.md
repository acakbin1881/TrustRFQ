<objective>
Put a real gate between an untrusted maker server and the taker's wallet. Every quote that reaches
the panel has already had its economics, fee, expiry, network binding, token identities, and
decoded authorization tree checked against something the maker does not control. A doctored quote
is dropped silently on the fan-out path; it never becomes a row the taker can click, and it never
becomes a wallet prompt.

Purpose: this is the phase's actual security boundary. The contract does reject a mismatched fee
and an expired order, but only at settlement — by then the taker has already been shown a prompt
they were asked to trust. TAKER-03 exists precisely to move that rejection in front of the prompt.

Output: `src/core/rfq/validate.ts` (pure, fail-closed), its suite, the live `get_config` read, the
panel's reject-before-prompt path, and the D-12 failure knobs in the stub maker that prove all of
it under the headless driver.
</objective>

without a network, and what lets the separate-repo taker SDK lift it unchanged.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| maker quote server -> `validateQuote` | The full untrusted surface: order terms, fee, expiries, token addresses, and the authorization entry itself |
| `rfq_swap.get_config` -> desk | Trusted (on-chain, read-only simulation), and therefore the reference the maker's `feeBps` claim is measured against |
| `validateQuote` -> wallet prompt | The gate. Nothing that fails validation may cross it. |
