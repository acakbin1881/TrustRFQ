<objective>
Close the one blocking gap from 02-VERIFICATION.md: per-maker fan-out isolation. Today a single
registered maker that answers with a value-level malformed amount — non-numeric, missing, or the
wrong JSON type — throws out of `validateQuote`, escapes `fanOutMakerSideOrder` entirely, and
destroys every other maker's genuinely valid, correctly signed quote in the same pass. After this
plan, that maker's quote is one rejection among many and every well-behaved maker's quote still
reaches the taker.

Purpose: `rfq_registry` registration is permissionless and stake-gated, not identity-gated, so this
is a live availability vector, not a hypothetical. One staked maker — malicious or merely buggy —
can deny quotes to every taker for a pair on every refresh. It also contradicts the promise
`validate.ts`'s own header comment makes: a rejection is supposed to be scoped to the quote that
earned it, never applied to everyone.

Output: guarded numeric reads in `src/core/rfq/validate.ts`, a per-quote catch at the fan-out call
site in `src/data/rfqNetwork.ts`, and regression tests at both layers — the mixed-pass one observed
RED before the fix exists, so the test is proven to exercise the gap rather than merely accompany it.
</objective>

## Value-edge probe rows (TAKER-02 scope)

The phase has no plain SPEC.md, so the deterministic edge probe returned 13 unresolved rows across
all 8 phase requirement IDs. Only the TAKER-02 value-edge rows are in this plan's scope; the rest
belong to already-executed plans 02-01 through 02-05 and are not reopened here.

These rows were MEASURED against `toAtomic`'s actual body, not reasoned about. The distinction
matters: half of them do not throw at all, so a test written on the assumption that "malformed
means throws" would assert the wrong reason and pass for the wrong cause.

| Input to `order.takerAmount` | Measured `toAtomic` result | Expected rejection | Covered by |
|---|---|---|---|
| `abc` | throws SyntaxError | `malformed_field` | Task 1 + Task 2 |
| field absent (`String(undefined)`) | throws SyntaxError | `malformed_field` | Task 2 |
| JSON `null` | throws SyntaxError | `malformed_field` | Task 2 |
| JSON object | throws SyntaxError | `malformed_field` | Task 2 |
| `1,000` / `1e5` / `NaN` / `Infinity` | throws SyntaxError | `malformed_field` | Task 2 (at least one) |
| `` (empty string) | parses to 0 | `economics_mismatch` | Task 2 |
| whitespace only | parses to 0 | `economics_mismatch` | Task 2 (optional) |
| `-1` | parses to -10000000 | `economics_mismatch` | Task 2 (at least one of this group) |
| `0x10` | parses to 160000000 (hex accepted) | `economics_mismatch` | Task 2 (at least one of this group) |
| 40-digit value | parses, no overflow guard | `economics_mismatch` | Task 2 (at least one of this group) |
| `0.1.2` | parses to 1000000 (extra segment dropped) | `economics_mismatch` | not required |

Recorded, deliberately NOT fixed here: `-0.5` converts to a POSITIVE 5000000, because the sign lives
on the whole part and the fractional part is added unsigned. No economic hole follows from it in
this phase — a taker amount that disagrees with the request is rejected by the economics check and a
maker amount that disagrees with the signed tree is rejected by the tree check, and the contract
rejects non-positive amounts on its own — but it is a real latent quirk in a signature-boundary
module. It belongs in a follow-up capture against `src/core/rfq/order.ts`, not in a gap-closure plan
whose whole premise is that order encoding for valid inputs does not move.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| permissionless `rfq_registry` -> discovered URL set | Any staked address can put any URL in front of the desk's fan-out. Membership is a spam price, not vetting. |
| maker JSON-RPC response -> `getMakerSideOrder` | The response passes only a truthiness check on `order` and `authEntry`; every field value beyond that is arbitrary attacker-chosen data. |
| `validateQuote` -> `fanOutMakerSideOrder`'s loop | The boundary this plan repairs: a verdict must be per-quote, and so must a failure to reach a verdict. |
| per-pass `get_config` / ledger reads -> the whole pass | Trusted on-chain reads with no safe fallback; a failure here must stay fatal to the pass. |
