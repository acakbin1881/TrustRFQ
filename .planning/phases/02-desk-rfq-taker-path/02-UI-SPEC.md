# Phase 2 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Positioning (POS-D1/UI-D1, locked — inherited from CONTEXT.md and REQUIREMENTS.md, not re-litigated here):**
this contract governs a deliberately minimal reference panel, not a product surface. Every
element below composes the desk's EXISTING hand-authored design system (`public/styles.css` +
`public/intent.css`); nothing here proposes a new component library, a new token, or a new
visual language. Desk metrics (clicks, prompt counts) are never evidence — this contract exists
only so the executor can build the panel without inventing look-and-feel decisions mid-implementation.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — hand-authored CSS design system (`public/styles.css` "milky desk" tokens + `public/intent.css` additive layer), no component framework, no shadcn/Tailwind |
| Preset | not applicable |
| Component library | none — plain React + hand-written CSS classes; Radix/base-ui not present in `package.json` |
| Icon library | none — hand-authored inline SVG (matches the existing `AddressSeal`/chevron/orb-spinner pattern; no icon package installed) |
| Font | `--font-display` / `--font-body` = Inter (headings, body copy); `--font-mono` = IBM Plex Mono (micro-labels, addresses, amounts-as-data, countdowns) — both already loaded, no new font |

**Why no shadcn init:** `components.json` is absent, and this IS a React + Vite project, so the
standard shadcn gate applies in principle. It is declined here as a deliberate call, not an
oversight: CLAUDE.md states the desk's existing stylesheet is "a compatibility contract with
intent.css and the JSX that hardcodes them — never rename or drop them, only change values," the
project's "Pinned deps" convention deliberately avoids adding runtime dependencies for a phase
that needs none (RESEARCH.md: "no new npm packages are required for this phase"), and POS-D1/UI-D1
mandate the desk stay a minimal thin shell, not grow a second design system. Introducing shadcn for
one panel would fork the desk's visual language rather than extend it. This is the reasonable
call per the project's own written constraints, not a request left open for the user.

## Spacing Scale

Declared values (must be multiples of 4) — the GSD default 8-point scale, adopted for every NEW
element this phase introduces:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, badge inner padding (mirrors `.badge`'s existing `gap: 7px` rounds to this family) |
| sm | 8px | Compact gaps inside a quote row (price ↔ countdown ↔ chevron) |
| md | 16px | Default gap between quote rows, panel-internal padding |
| lg | 24px | Panel section padding (mirrors `.order` card's `22px 24px`) |
| xl | 32px | Gap between the pair/amount controls and the quote list |
| 2xl | 48px | not used this phase (no page-level section break inside a single panel) |
| 3xl | 64px | not used this phase |

Exceptions: the existing desk stylesheet is a hand-tuned system that does **not** strictly follow
4-multiples everywhere (e.g. `13px`, `15px`, `26px` recur throughout `styles.css`/`intent.css`).
Where this phase's new markup sits directly beside an existing primitive (the `.order` card,
`.badge`, `.hint`, `.empty` states, `.btn`), REUSE that primitive's exact padding/gap values
as-is rather than rounding them to the 4-point scale — visual seams between old and new desk
chrome are a worse outcome than a strict scale. The 4-point scale above applies to genuinely new
layout (the quote-row list itself, the pair/amount control group).

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 15px | 400 (regular) | 1.5 |
| Label | 11px | 600 (semibold) | 1.4 |
| Heading | 17px | 600 (semibold) | 1.3 |
| Display | 24px | 700 (bold) — documented exception, see below | 1.2 |

Font sizes in play: 11px (mono micro-labels/countdowns), 15px (body/hints), 17px (panel title),
24px (quote amount figures) — 4 sizes, matching the template's 3-4 guidance.

**Weight exception, documented:** the contract's 2-weight rule is 400/600 for everything this
phase writes fresh. The one exception is the quote row's receive-amount figure at **700**, which
directly reuses `.legbox__v`'s existing weight (`public/styles.css:1101-1114`, `font-weight:
700`) — the RFQ quote row is modeled on the existing OrderCard `.legbox` pattern (a labeled
amount pill), and giving it a different weight than every other "amount" in the desk would be the
inconsistency, not the fix. Mono micro-labels (`.field__label`, `.settle__title` pattern) already
render at 500/600 in the existing system; this phase standardizes new mono labels at 600 to stay
inside the 2-weight budget without a visible regression (500→600 on an 11px uppercase label is not
perceptible).

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--bg` (#EFF1FA canvas) / `--bg-raised` (#FFFFFF cards) | Panel background, quote-list card surface |
| Secondary (30%) | `--bg-sunken` (#EFF1F7) | Quote row wells (mirrors `.legbox`), amount input field, disabled states |
| Accent (10%) | `--gold` family (#16171D ink accent — NOT literal gold) | Reserved for: the "Accept quote" primary CTA fill (`.btn--gold`), the best-preselected quote row's selection ring/border, the section-nav glyph circle for the new RFQ tab (matches the existing `.section-fab__glyph` pattern) |
| Destructive | `--red` (#C93838) | Reserved for: expired-quote countdown text, drop/refusal error copy, settlement failure text (`.settle__err`) — never for the "Re-quote" button, which is a neutral retry, not a destructive action |

Accent reserved for: **only** the three elements listed above. Never used for informational
copy (the "N makers found" indicator, countdowns, price figures render in `--text-1`/`--text-2`,
not accent ink) — this matches the existing desk's discipline where `--gold` marks the one
committed action per screen, not decoration.

Note (informational, not a template row): `--green` (#0E7C4A) is the desk's existing SECOND
semantic color for success/settled states (`.badge--accepted`, `.stepper__step.is-final`) and
carries over unchanged for the RFQ settlement confirmation (swap-event-confirmed state), matching
`SettlementStrip`'s existing pattern. It is not "the destructive color" — `--red` fills that role
per the table above.

## UI Considerations

> Populated by the ui-phase UI-consideration probe (Step 9.5) and lifted by plan-phase's
> `## UI Considerations` lift rule via the identical rule as SPEC `## Edge Coverage`. Shape-rooted UI *state*
> coverage (empty / loading / error / populated / partial / overflow / zero-one-many / long-text).
> Empty-state and error-state COPY live in `## Copywriting Contract` above — this section covers
> state coverage and REFERENCES those rows rather than restating the copy (de-dup).

Applicable state considerations resolved: 15 covered, 2 backstop, 0 unresolved

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | quote-list | ✅ covered | Zero discovered makers renders the "No makers registered" empty card; zero valid quotes after fan-out renders the distinct "No quotes available" empty card — copy rows above. No maker list or URLs shown either way (D-02). |
| empty | pair-select | ✅ covered | No pair selected leaves the amount field and CTA disabled with a passive placeholder ("Choose a pair to see live quotes."). |
| empty | amount-input | ✅ covered | Empty amount disables the CTA and suppresses fan-out; mirrors `Ticket.tsx`'s existing amount-gates-send wiring. |
| loading | quote-list | ✅ covered | While the parallel `getMakerSideOrder` fan-out is in flight (2-3s cap, TAKER-02), the list area shows the existing orb-spinner busy pattern (`.btn__orb .spin`) inline, not a full-page loader. |
| loading | re-quote-button | ✅ covered | Disables and shows the spinner for the duration of the re-fan-out (same `.is-busy` mechanism as `.ticket__swap-btn`). |
| loading | accept-button | ✅ covered | Reuses the existing settlement busy pattern (toast + `.stepper` progression + tx link) per the Discretion note — no new busy UI invented. |
| error | quote-list | ✅ dismissed | A fan-out that returns zero valid quotes (all dropped/timed-out/malformed per D-12's failure knobs) is presentationally identical to the empty state; no separate error card. |
| error | re-quote-button | ✅ covered | A failed re-fan-out surfaces via the existing Toast `err` pattern; prior (now-expired) rows stay visible rather than being cleared. |
| error | accept-button | ✅ covered | Settlement failure reuses `.settle__err`; D-09's price-guarded retry surfaces as a visible inline note (not a silent retry) per the Copywriting Contract rows above. |
| populated | quote-list | ✅ covered | D-04: ranked by price, best preselected, taker may pick another row; each row shows price + receive amount + countdown only (D-07 — no maker identity in the UI). |
| partial | quote-list | ✅ dismissed | A quote is atomic — TAKER-02 drops any malformed response outright; there is no partial-quote row to render. |
| partial | pair-select / amount-input | ✅ dismissed | Tokens resolve only from the curated allow-list (TAKER-05) and the amount is a single numeric field; no partially-filled state exists. |
| overflow | quote-list | ✅ covered | Cap the visible list to 6 rows with internal scroll past that (mirrors `OfferList`'s existing card-list scroll pattern) rather than growing the panel unbounded. |
| overflow | n-makers-indicator / trustline-note | ✅ dismissed | Both are single short lines at label/hint scale (max ~3 digits for the count, one sentence for the note) — no wrap risk observed in the equivalent existing `.eyebrow`/`.hint` usages. |
| overflow | settlement-confirmation | ✅ covered | The tx hash renders truncated + linked via the existing `trunc()` helper (`src/core/tokens.ts`), the same pattern already used for the wallet-chip address — never the raw 64-char hex inline. |
| zero-one-many | quote-list | ✅ covered | Zero → the empty card; one → a single row rendered as a normal (already-best) row, no singular-copy branch needed since rows carry no count language; many → the ranked, capped-and-scrollable list (overflow row above). |
| long-text | quote-row amounts | ✅ covered | Figures use tabular-nums and the existing `.legbox__v` numeric style at a fixed size — the RFQ amount is the sell-side figure the taker already typed, not the giant Ticket hero digits, so no dynamic shrink-on-length logic is needed. |
| long-text | amount-input | 🧪 backstop | Very large typed amounts (approaching the `amountTooLarge` cap `Ticket.tsx` already enforces) are assumed to reuse that same validation for the RFQ amount field; not independently re-verified for this new input in this research pass — implementation/tests should confirm the cap applies identically. |
| long-text | accept-button / re-quote-button labels | ✅ dismissed | Fixed short microcopy ("Accept quote", "Re-quote"), never dynamically generated or user-influenced length. |

## Implementation Notes (non-template, executor-facing)

These are not part of the six checker dimensions but record concrete layout decisions the
executor needs and that were not already pinned by CONTEXT.md/RESEARCH.md:

- **New `data-panel` name: `rfq`.** Must be added to BOTH `src/App.tsx` (new `TabName` union
  member `'rfq'`, a fourth `<div className="panel" data-panel="rfq">` block) AND
  `public/intent.css` (a `[data-panel="rfq"]` layout rule) in the same change — the known silent
  layout-loss gotcha (CLAUDE.md, RESEARCH.md Pitfall 3). Nav entry: `{ id: 'rfq', label: 'RFQ',
  glyph: '⇄' }` — no count badge (D-03: no persistence, nothing to count; the other two tabs'
  counts come from Supabase-backed order state the RFQ lane deliberately has none of).
- **Component shell:** a new `src/ui/RfqPanel.tsx`, composing existing primitives only —
  `TokenSelect` (pair legs), `AddressSeal`-adjacent visual language is NOT needed (D-07: no
  maker identity shown), `Toast` (fan-out/settlement errors), the existing `.order`/`.legbox`
  card classes for each quote row, `.stepper`/`.settle` classes for the confirmation state. No
  new CSS component class family beyond what's listed in this contract's Spacing/Color/Typography
  tables (e.g. `.rfq-row`, `.rfq-countdown`, `.rfq-indicator` — thin wrappers around existing
  primitives, not a new visual system).
- **Quote row layout:** reuse the `.legbox` two-line pill (label + tabular-nums value) for the
  receive amount, with the countdown rendered as a small mono chip to its right (visually
  equivalent to `.legbox__t`'s token-tag chip, repurposed for a time string) — no new pill shape.
  The best-preselected row gets the accent-ring treatment (Color contract, Accent row) instead of
  a checkbox/radio; selecting another row moves the ring.
- **Settlement confirmation:** in-panel only (D-03 — no Supabase write, no navigation away),
  showing exact settled amounts + a truncated, linked tx hash + the existing green
  swap/settled visual language (`--green`, `.badge--accepted`'s color, `.stepper__step.is-final`).
