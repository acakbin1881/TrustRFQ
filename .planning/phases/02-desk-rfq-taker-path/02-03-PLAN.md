<objective>
Turn the tracer's single-quote path into a real comparison surface: N makers discovered and
announced in one line, every validated quote ranked by price with the best preselected, a live
countdown per row, expired rows dropping out, and one deliberate manual refresh. Then cover the
states the UI contract requires — empty, loading, error, populated, overflow, zero-one-many, and
long text.

Purpose: the taker's only defensible reason to prefer one quote over another is price and time
remaining. Everything else the desk could show — who quoted, how much they staked, how many tokens
they registered — is either irrelevant to the guarantee or actively misleading about it. This plan
builds exactly the surface that decision needs and nothing beyond it.

Output: `src/core/rfq/discover.ts` (pure ranking), the panel's full state coverage, the
`[data-panel="rfq"]` layout rules that carry it, and driver scenarios for the empty and expiry
paths.

**UI considerations recorded as dismissed** (from 02-UI-SPEC.md `## UI Considerations`, carried
here so nothing is silently dropped): `error | quote-list` — a fan-out returning zero valid quotes
is presentationally identical to the empty state, so no separate error card exists;
`partial | quote-list` — a quote is atomic, a malformed response is dropped outright, so no partial
row can exist; `partial | pair-select / amount-input` — tokens come only from the curated
allow-list and the amount is one numeric field, so no partially-filled state exists;
`overflow | n-makers-indicator / trustline-note` — both are single short lines at label scale with
no observed wrap risk; `long-text | accept-button / re-quote-button labels` — fixed short microcopy,
never user-influenced.
</objective>

  <behavior>
    - `intersectUrls(a, b)` returns only strings present in both arrays, preserving the order of the first array.
    - `intersectUrls` with either side empty returns an empty array; with a null or undefined side it returns an empty array rather than throwing.
    - Duplicate URLs within one side collapse to a single entry in the intersection.
    - `quotePrice(quote)` returns the taker's rate as makerAmount over takerAmount, computed from the atomic decimal strings without floating-point rounding of the inputs.
    - `rankQuotes` orders by best price first (most received per unit sold).
    - `rankQuotes` on two quotes with exactly equal price preserves input order, and calling it twice on the same input yields the identical order both times.
    - `rankQuotes([])` returns an empty array; `rankQuotes([one])` returns that one quote.
    - `bestQuote(ranked)` returns the first element, or null for an empty list.
    - `dropExpired(quotes, nowSeconds)` removes quotes whose expiry is strictly less than now and KEEPS a quote whose expiry equals now, matching the contract's strictly-greater-than expiry check.
    - `fmtCountdown(expirySeconds, nowSeconds)` returns a zero-padded mm:ss string while time remains and the exact string "Expired" at or past zero.
  </behavior>
  <action>
Write `src/core/rfq/discover.ts` as a pure module in the style of `src/core/oracle.ts`: no network,
no globals, no wallet, every input passed in. It owns the two decisions the panel must not make for
itself — which makers are common to both token lists, and what order the quotes go in.

`intersectUrls(makerTokenUrls, takerTokenUrls)` is a plain set intersection preserving the first
array's order, defensive against a null or undefined side (a failed registry read must yield an
empty list, never an exception that blanks the panel). It performs NO url normalization: no
trailing-slash folding, no case folding, no scheme coercion. That is a deliberate, recorded choice,
because no source artifact specifies a normalization rule and inventing one would silently merge
two endpoints a maker registered as genuinely distinct. Say so in the module header so a future
reader knows it was decided rather than forgotten.

`quotePrice`, `rankQuotes`, `bestQuote`, `dropExpired` and `fmtCountdown` complete the surface.
Ranking is the spec's selection rule — best price, exactly as the reference implementation
picks — presented as a list; the list is presentation, not a different algorithm (D-04). Compute
price from the atomic decimal strings using bigint arithmetic scaled to a fixed number of digits so
two mathematically equal prices compare exactly equal, then use a stable comparison so equal prices
keep input order. A sort that reorders ties non-deterministically would move the preselected row
under the taker between renders, which is the one thing a preselected primary action must never do.

Write `src/core/rfq/discover.test.ts` covering every behavior line, with explicit cases for the
equal-price stability property (assert the same output twice), the empty and single-element inputs,
and the expiry-equals-now boundary.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `rfq_registry` -> discovery line | A permissionless, stake-gated listing rendered as a count the taker reads as information about the market |
| maker quote server -> ranked list | Prices compete for the preselected position, which is the row the taker is most likely to accept |
| shared clock -> countdown -> row removal | The countdown is what tells the taker how long the quoted price is binding |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-13 | Spoofing | discovery line in `src/ui/RfqPanel.tsx` | medium | mitigate | The line states a count and nothing else — no maker identity, URL, stake, or endorsement language (D-02, D-07). A count cannot be read as vetting, and validation runs identically regardless of who quoted. |
| T-02-14 | Tampering | preselected row in `src/core/rfq/discover.ts` | medium | mitigate | Ranking is a deterministic, tie-stable comparison over bigint-scaled prices, tested by asserting identical output across two calls. A non-deterministic tie order could move the preselected row under the taker between renders. |
| T-02-15 | Denial of service | `rankQuotes` and the rendered list | low | mitigate | The visible list is capped at 6 rows with internal scroll, and `max_makers_per_token` caps discovery on-chain at 100, so a maker-count flood cannot grow the panel or the render cost unbounded. |

| T-02-17 | Tampering | countdown and expiry filtering | medium | mitigate | `dropExpired` keeps a quote whose expiry equals now, matching the contract's strictly-greater-than test, so the client is never stricter than the chain and never shows a live row for a quote the chain would refuse.
