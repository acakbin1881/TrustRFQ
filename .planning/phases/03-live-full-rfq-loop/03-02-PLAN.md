<objective>
Wire this repository to the live maker: add its origin to the desk's CSP allow-list, teach the
existing RFQ E2E driver a live-maker mode that spawns nothing and patches nothing, and settle the
first real swap driven by a browser against a genuinely discovered, genuinely remote maker.

Purpose: Phase 2 proved the taker path against a local stub maker with Playwright route
interception patching discovery, injecting mode headers and de-duplicating registry results. Every
one of those patches is a stub-shaped hole in the E2E-02 claim. Live mode's defining property is
subtraction: no child process, no page.route, no header injection, no response patching — the desk
discovers a URL on-chain and the browser really talks to it over the public internet under a real
CSP.

Output: a CSP that permits exactly one new origin, a driver mode that proves discovery drove the
fetch, and one Testnet transaction settled end-to-end through the browser.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → maker origin | A cross-origin POST from the desk to a third-party https endpoint; the CSP is the only thing that decides whether it is permitted at all |
| `vercel.json` → the deployed edge | A single string change here changes the production security posture of every desk page |
| registry read → the URL the browser fetches | An attacker-controlled registry entry is a URL the desk will POST to |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-07 | Tampering | `vercel.json` `connect-src` | high | mitigate | The origin is added literally with no scheme- or host-wildcard; the task's automated verify parses the CSP and fails on any source containing an asterisk or a bare scheme, and separately asserts `script-src` is unchanged. A wildcard here would let any registered maker URL reach the network, which is precisely what the curated allow-list posture (D-11) rejected |
| T-03-08 | Spoofing | registry-sourced maker URL | medium | mitigate | The desk can only reach origins the CSP allow-lists, so a hostile registry entry pointing at an unlisted origin is blocked by the browser before any request leaves. The economic protection is separate and already shipped: `validateQuote` rejects any quote whose decoded auth-entry tree does not match the order terms, so a rogue maker cannot produce a settleable quote regardless of which URL served it |
| T-03-09 | Information Disclosure | `public/otc-config.js`, `src/` | medium | mitigate | The maker's origin is deliberately NOT added as runtime config or as any constant in bundled source; the automated verify greps the non-comment body of both the runtime config and the driver for the origin string and fails if it appears. This keeps success criterion 1 honest and avoids a second place that must be edited on a Testnet reset |
| T-03-10 | Repudiation | live-run report | medium | mitigate | Every fan-out attempt, including dropped ones, is recorded in the `attempts` array with its own timing and row count, so the recorded evidence cannot be a hand-picked successful attempt |
</threat_model>
