<objective>
Expand the proven single-direction live slice into the full recorded run: both directions of the
curated XLM/USDC pair, five exact balance-delta assertions per settlement, and one committed
machine-readable artifact carrying everything a future reader needs to believe the claim.

Purpose: success criterion 3 asks for more than a transaction hash — it asks that the hash, the
swap event and all four balance deltas confirm the exact quoted amounts plus the maker-paid fee. A
run that prints a hash and stops has not measured that. D-09 additionally requires both directions,
because XLM to USDC exercises the taker trustline path live while USDC to XLM exercises the maker
paying out native XLM. Success criterion 4 asks for reproducibility, which starts with a
machine-readable record rather than a paragraph of prose.

Output: a driver that fails loudly on a single mismatched stroop, two settled Testnet transactions,
and `docs/evidence/live-rfq-run.json`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| quoted amounts → settled amounts | The gap a dishonest or buggy maker would exploit; the delta assertions are what close it |
| `rfq_swap` config → the driver's expectations | Reading `fee_bps`/`fee_collector` from the contract instead of a constant is what keeps the assertion honest across a redeploy |
| run artifact → the public repository | A committed evidence file is a place secrets can leak by accident |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-11 | Tampering | quoted vs settled amounts | high | mitigate | Five exact stroop-level deltas per settlement, derived from the quote the desk displayed and the contract's own `fee_bps`, with no tolerance window. A maker that settles anything other than the quoted terms fails the run instead of producing a green transcript |
| T-03-12 | Information Disclosure | `docs/evidence/live-rfq-run.json` | high | mitigate | The record is restricted to public facts (addresses, contract ids, amounts, transaction hashes, timings); an acceptance criterion greps the committed file for the Stellar secret-key pattern and for any signed auth-entry blob and fails on a match |
| T-03-13 | Repudiation | the recorded evidence | medium | mitigate | Every attempt is recorded, not only the successful one; the canonical run is forbidden from being restarted to produce a cleaner transcript, and re-runs must be counted and explained in the SUMMARY |
| T-03-14 | Tampering | fee-collector identity collision | low | mitigate | The driver asserts the fee collector is distinct from both the maker and the taker before trusting the five-way delta split; a collision would silently merge two deltas and weaken the proof without any visible failure |
</threat_model>
