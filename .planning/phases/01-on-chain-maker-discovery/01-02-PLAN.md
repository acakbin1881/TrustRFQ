<objective>
Expand the proven tracer slice outward: a maker can declare which tokens it quotes and which
protocols it speaks, priced per token, bounded on both axes, and a client can discover makers by
token.

Purpose: this is the capability the whole registry exists for. `get_urls_for_token` is the exact
call Phase 2's desk makes twice per pair, and the two independent bounds it sits behind — a fixed
per-maker cap and an admin-tunable per-token cap — are what keep an unbounded `Vec` from bricking
the contract against Soroban read limits.

Output: `add_tokens`, `remove_tokens`, `get_urls_for_token`, `add_protocols`, `remove_protocols`,
an `eject` that unwinds every list the maker is in, and the tests that pin all of it.
</objective>

  <action>
Add the token half of the registry to `contracts/rfq_registry/src/lib.rs`, plus its tests.

**`add_tokens(env, maker: Address, tokens: Vec<Address>)`.** First statement `maker.require_auth()`.
Return `Error::EmptyInput` on an empty input `Vec`. Load `Maker(maker)` or return
`Error::NotRegistered` (D-07 — `set_url` is the only entry point that may create a registration).
Enforce the per-maker cap up front: if `cfg.tokens.len() + tokens.len()` exceeds
`MAX_TOKENS_PER_MAKER`, return `Error::TooManyTokens`. Then a single pass over the input: for each
token, reject with `Error::TokenAlreadyAdded` if it is already in `cfg.tokens` (which also catches an
intra-call duplicate, because the growing `cfg.tokens` is what is checked); read `Token(t)`'s current
`Vec<Address>` (absent means empty) and reject with `Error::TokenListFull` if its `len()` is at or
above the cap; push the maker onto that list, write it back, and bump its TTL; push the token onto
`cfg.tokens`.

The per-token cap value MUST be re-read from instance storage on every `add_tokens` call, never
cached in per-maker or per-token persistent state. D-04's rule is that lowering the cap blocks new
additions but never evicts existing entries, and that is only true if the comparison is against the
current value at the moment of the call.

Compute the stake as `per_token_cost * tokens.len()` with checked multiplication mapped to
`Error::MathOverflow` (never a silent wrap), transfer it from `maker` to
`env.current_contract_address()` via `token::Client`, add it to `cfg.staked`, write `Maker(maker)`
back, bump its TTL, and emit `TokensAdded`.

Do not write manual unwind code for the failure paths. An early `Err` return discards every storage
write and every token transfer made in the invocation — that host guarantee is exactly what makes
D-05's "no state change, no funds move on error" achievable with straightforward early returns.

**`remove_tokens(env, maker: Address, tokens: Vec<Address>)`.** Same auth, empty-input, and
`NotRegistered` preamble. For each token: find its index in `cfg.tokens` and return
`Error::TokenNotFound` if absent (D-05); remove it by index from `cfg.tokens`; load `Token(t)`, find
the maker's index, and remove by index. Use index-based removal (`Vec::remove`), not a swap-remove:
the surviving entries' relative order is an observable of `get_urls_for_token` and must stay stable.
If the resulting `Token(t)` list is empty, remove the storage key entirely rather than storing an
empty `Vec`, so an abandoned token stops paying rent; otherwise write it back and bump its TTL.
Refund `per_token_cost * tokens.len()` from the contract to the maker, subtract it from `cfg.staked`,
write `Maker(maker)` back, bump TTL, and emit `TokensRemoved`.

**`get_urls_for_token(env, token: Address) -> Vec<String>`.** No auth, no writes, no TTL bump — it is
a pure read intended for RPC simulation. Read `Token(token)`; if absent return an empty `Vec<String>`.
Otherwise map each `Address` to its `Maker(a)` entry's `url`, skipping any address whose `Maker`
entry is missing (defensive: the lists are kept in sync, but a read-only discovery call must never
panic for a client). Return the urls in the list's own order.

**Extend `eject`.** Before deleting `Maker(maker)`, iterate `cfg.tokens` and remove the maker from
each `Token(t)` list (deleting the key when the list becomes empty), so no dangling address is left
behind for `get_urls_for_token` to resolve. The refund stays `cfg.staked` in full — one transfer, not
a recomputation from current cost values, because `staked` records what was actually paid and the
admin may have retuned costs since (D-04).

**Tests.** Extend `contracts/rfq_registry/src/test.rs` to cover the `<behavior>` list. Include one
test that populates a `Token(t)` list with 20 distinct registered makers and asserts
`get_urls_for_token` returns all 20 urls in insertion order — this is the read-volume probe for the
flagged assumption below. Fund every actor that appears in a rejection test.
  </action>
